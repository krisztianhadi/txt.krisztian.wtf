# Architecture

## Pipeline

```
push to main
   |
   v
.github/workflows/pages.yml (GitHub Actions)
   |  actions/jekyll-build-pages@v1
   |  -> runs the github-pages gem (232) exactly like legacy Pages
   v
_site/  (static output)
   |  actions/upload-pages-artifact + actions/deploy-pages
   v
txt.krisztian.wtf
```

No plugins, no Gemfile in this repo. The workflow's container already has
the whole github-pages gem set baked in, so CI needs zero installs and the
build is reproducible. A repo Gemfile would not be honored anyway (the
action only warns about it) - that is why there is none.

Two github-pages gem defaults worth knowing:

- It excludes `CNAME` from the output. The workflow therefore copies
  `CNAME` into `_site/` after the build so the artifact keeps the custom
  domain (see `.github/workflows/pages.yml`).
- It applies the `jekyll-theme-primer` theme when the config does not name
  one. Harmless here: `_layouts/default.html` and `post.html` always win,
  so primer only adds its unused `assets/css/style.css` to the output.

## Source layout

| Path | Role |
| --- | --- |
| `_config.yml` | Site title/url/timezone, permalinks, markdown settings |
| `index.html` | Homepage: masthead + entry loop (title, date, two-block preview, continue reading). Its front matter `subtitle` is rendered as the tagline *and* used as the meta/OG description |
| `_layouts/default.html` | HTML shell (head, meta, css, RSS autodiscovery) |
| `_layouts/post.html` | Single post page: wordmark (links home), title, date, content, trailing back link |
| `_posts/*.md` | Blog posts, one file per post, dated filename |
| `assets/css/style.css` | Local stylesheet - the whole look (see below) |
| `assets/css/fonts.css` | `@font-face` rules for the self-hosted fonts (generated) |
| `assets/fonts/*.woff2` | Self-hosted Source Serif 4 (roman + italic) and Fraunces |
| `tools/fetch-fonts.mjs` | Downloads/refreshes the webfonts and rewrites `fonts.css` |
| `assets/images/` | Post images (copied to output verbatim) |
| `feed.xml` | RSS 2.0 template rendered from `site.posts` |
| `CNAME` | Custom domain; Jekyll copies it into `_site/` so Pages keeps it |
| `favicon.svg`, `favicon-32.png`, `favicon.ico`, `apple-touch-icon.png` | Lowercase "k" in Fraunces on an ink tile (see `tools/gen-favicon.py`) |
| `tools/gen-favicon.py` | Deterministic favicon generator: instantiates the self-hosted Fraunces at weight 600, bakes the "k" outline into `favicon.svg`, and rasterises the PNG/ICO set (needs fonttools + brotli + pillow) |
| `scripts/build.sh` | Local build through the CI container (sources copied in, `_site` out) |
| `scripts/dev.sh` | Dev server: source watcher + rebuild + browser-sync live reload |
| `scripts/external-links.py` | Post-build outbound-link annotation (see below) |

## Notes

- `masthead:` in `_config.yml` is the visible wordmark: the homepage `h1`
  and the article-page backlink to home. `title:` is the longer name used in
  `<title>`, `og:site_name` and the feed.
- `url` is the absolute production URL; the RSS feed uses it for absolute
  links. Local preview therefore shows production URLs inside the feed -
  expected.
- `timezone: Asia/Bangkok` controls RSS/pubdate offsets (UTC+7).
- Permalinks are `/:title/` (no dates in URLs).
- Shared styling comes from https://krisztian.wtf/style.css (same visual
  family as the other krisztian.wtf pages); `blog.css` only patches what
  Jekyll output needs (rouge highlight colors, code fences, post list).
- Post dates in filenames must match reality: a future-dated file is not
  shown unless `future: true` (set in config).

## Design

All styling is local (`assets/css/style.css`) and **no third party is
contacted at runtime**: the webfonts are self-hosted (`assets/fonts/*.woff2`,
declared in `assets/css/fonts.css`, generated by `tools/fetch-fonts.mjs`).
Both families fall back to the system serif stack if they fail to load.

- Paper look: off-white background + dark gray text.
- Type: **Source Serif 4** for text (`--font-serif`) and **Fraunces** for
  headlines (`--font-display`, weight 600), both falling back to `ui-serif`,
  Georgia, Times. Code stays monospace.
- Fraunces renders at its own axis defaults - `SOFT 0`, `WONK 1` (the font
  ships wonk on) - with `font-weight: 600`. No `font-variation-settings`
  override; add one to experiment (SOFT 0-100 softens the terminals, and
  SOFT 100 reads saccharine).
- Headline icons are lucide SVGs drawn as CSS masks (no glyph dependency).
- Night mode: pure `prefers-color-scheme` - follows the OS, no toggle, no JS.
  Colors are CSS custom properties swapped in a `@media (prefers-color-scheme: dark)`.
- Accessibility: body text ~13:1, muted labels ~5:1, links ~6.7:1 (light)
  and ~11:1 (dark) contrast; visible focus ring; `color-scheme` set so
  form controls/scrollbars match.
- Rouge token colors are mapped through custom properties so highlighted
  code reads in both modes.

## Page identity (title, description, image)

`_layouts/default.html` derives each page's metadata, article-first:

| Field | Resolution order |
| --- | --- |
| browser `<title>` | page title + " — " + site title (homepage: site title alone) |
| `og:title` / `twitter:title` | the page's own title, else the site title |
| `<meta name="description">`, `og:description` | front-matter `description` -> front-matter `subtitle` -> the page's own text (32 words, word-safe) -> `site.description` |
| `og:image` / `twitter:image` | front-matter `image` -> the generated card for this post (see below) -> `site.og_image` -> none |

- Posts also emit `og:type: article` and `article:published_time`.
- `twitter:card` is `summary_large_image` only when an image resolves,
  otherwise `summary`.
- Front-matter keys a post can set: `title`, `date`, and optionally
  `description` (hand-written summary) and `image` (per-article share
  image). With `image` set, an article's card is complete: own title, own
  summary, own picture.

## Share cards

Every post gets a 1200x630 card that mirrors how the entry looks on the
homepage: masthead + date on top, the article title in Fraunces, then the
opening text fading out.

```sh
node tools/gen-og.mjs           # writes assets/images/og/<slug>.png (skips fresh cards)
node tools/gen-og.mjs --force   # rebuild all
CHROME_PATH=/path/to/chromium node tools/gen-og.mjs   # if playwright browsers are missing
```

- Deterministic: fixed viewport, fixed type scale, the same Google Fonts the
  site uses, headless Chromium screenshot. No AI generation.
- The slug matches the post permalink (`/:title/`), so the layout can find
  the card by convention - `_layouts/default.html` checks `site.static_files`
  for `assets/images/og/<slug>.png` and only then emits `og:image` +
  `twitter:image` + a `summary_large_image` card. A missing card means no
  broken image tag, never a 404.
- Cards are committed (CI does not render them): after editing a post, run
  the generator and commit the PNG. `scripts/dev.sh` does this automatically
  when a file under `_posts/` changes.
- The homepage gets a card too - `assets/images/og/home.png`, the masthead and
  tagline exactly as the page shows them (sources: `_config.yml` `masthead:`
  and `index.html` `subtitle:`), wired through `site.og_image` in
  `_config.yml`.

## External links

Jekyll runs in safe mode in the CI container (`_plugins` are ignored), so
link post-processing is a separate build step:

1. `.github/workflows/pages.yml` runs `python3 scripts/external-links.py _site`
   after the Jekyll build.
2. The script adds `target="_blank" rel="noopener"` + `class="ext"` to every
   anchor whose host is not txt.krisztian.wtf. `rel="noopener"` is mandatory
   with `target="_blank"` (tabnabbing protection).
3. `assets/css/style.css` renders `.ext::after` as the same lucide
   arrow-up-right icon krisztian.wtf uses (CSS mask over `currentColor`,
   so it inherits the link color) - outbound links show the brand icon.
4. Feed.xml is untouched (script only processes `.html` files).

Reasons: Markdown has no syntax for link targets, and kramdown cannot be
configured to add them globally; doing it at build time keeps posts plain
Markdown and the behavior consistent everywhere.

Note on the Fraunces axes: the Google-served Fraunces that we self-host
carries **only `opsz` and `wght`** - SOFT and WONK are not part of it, so the
site renders the standard cut at its default axis values. Anything that sets
Fraunces explicitly (the share cards, `tools/gen-favicon.py`) must pin `opsz`
to the size the page would use, otherwise it draws a different - text-sized -
cut. Fetching the upstream Fraunces release would be required to use SOFT/WONK.
