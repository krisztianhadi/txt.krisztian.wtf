# Writing Style Guide — Krisztián Hadi

## Purpose

This document defines the voice, tone, and formatting rules for any text generated
on behalf of Krisztián Hadi (website copy, case studies, CV bullet points, LinkedIn
posts, project descriptions, etc.). The goal is to sound like a real human — specifically,
like Krisztián — not like a corporate brochure or an AI assistant.

---

## Core Voice Principles

1. **Write like you talk.**
   If it wouldn't come out of your mouth in a conversation, rewrite it.

2. **Be direct.**
   Say the thing. Don't circle around it with qualifiers and filler.

3. **Use contractions.**
   "I don't" not "I do not." "It's" not "It is." "You're" not "You are."

4. **Vary sentence length.**
   Short punchy lines. Then a longer, more meandering one that takes its time
   and builds to a point. Rhythm matters.

5. **Have opinions.**
   "I don't believe in the wall between design and code" is better than
   "I value cross-functional collaboration."

6. **Be specific.**
   "Clicked five minutes after it was said out loud" is better than
   "rapid prototyping capabilities."

7. **Admit imperfection.**
   "I had no chance to gather user feedback" is more human than
   "iterative feedback loops were limited."

8. **Use humor sparingly but naturally.**
   A dry aside, a self-deprecating joke, a parenthetical "(sorry, not sorry)"
   — these make the text feel alive.

## Tone Spectrum

| Context | Tone |
|---------|------|
| Website intro / About page | Warm, confident, conversational |
| Case studies | Reflective, honest, process-oriented |
| CV / Resume | Professional but not stiff — still human |
| LinkedIn posts | Casual, insightful, no corporate speak |
| Project descriptions | Clear, enthusiastic, no fluff |

## Sentence & Paragraph Rules

### Do:
- Start sentences with "And" or "But" occasionally.
- Use em dashes — they're fine.
- Use parentheses for asides (like this).
- Break grammar rules if it improves flow.
- Write in first person ("I design," "I build," "I believe").

### Don't:
- Use passive voice unless absolutely necessary.
- Write sentences longer than 25 words on average.
- Use more than 3 clauses in a single sentence.
- Start every paragraph with "I" — vary it.
- Use perfect parallel structure in every list (too robotic).

These are instant "AI tells." Never use them:

| Banned | Why |
|--------|-----|
| "Delve" | Overused by LLMs |
| "Tapestry" | Same |
| "Landscape" (as in "the design landscape") | Vague and cliché |
| "In today's fast-paced world" | Instant cringe |
| "It's not just X, it's Y" | Overused AI structure |
| "Leverage" | Corporate speak |
| "Synergy" | Corporate speak |
| "Innovative solutions" | Says nothing |
| "Impactful experiences" | Says nothing |
| "Meaningful results" | Says nothing |
| "Passionate about" | Overused |
| "Seasoned professional" | Sounds like a LinkedIn cliché |
| "Results-driven" | Empty buzzword |
| "Detail-oriented" | Everyone says this |
| "Think outside the box" | Dead metaphor |
| "Game-changer" | Overused |
| "Cutting-edge" | Overused |
| "State-of-the-art" | Overused |

## Preferred Constructions

| Instead of... | Use... |
|---------------|--------|
| "I am responsible for..." | "I lead..." / "I build..." / "I design..." |
| "Utilized" | "Used" |
| "Facilitated" | "Helped" / "Ran" / "Led" |
| "Leveraged" | "Used" / "Built on" |
| "In order to" | "To" |
| "At this point in time" | "Now" |
| "Due to the fact that" | "Because" |
| "A large number of" | "Many" |
| "In the event that" | "If" |
| "Prior to" | "Before" |
| "Subsequent to" | "After" |

## Punctuation Rules

| Mark | Rule |
|------|------|
| **Em dash (—)** | Allowed. Use for asides, emphasis, or dramatic pauses. Don't overuse. |
| **En dash (–)** | Use for ranges (2022–2025). |
| **Hyphen (-)** | Use for compound words (open-source, user-centered). |
| **Semicolon (;)** | Allowed, but sparingly. |
| **Ellipsis (...)** | Allowed for trailing thoughts. Don't overuse. |
| **Oxford comma** | Yes, use it. |
| **Exclamation marks (!)** | Rarely. Only when genuinely excited. |
| **Question marks (?)** | Fine in rhetorical questions. |

## Formatting Rules

### Bullet Points:
- Keep them short — one line each if possible.
- Don't start every bullet with the same word.
- Mix in complete sentences occasionally.

### Headings:
- Use sentence case, not Title Case.
- Keep them short and clear.

### Links:
- Link to relevant pages naturally, not as "click here."
- Example: "I wrote about this in my [LastPass case study](url)."

### Images:
- Always add alt text.
- Captions should be conversational, not descriptive.

## Structural Guidelines

### Website Intro / About:
1. Start with a hook — who you are and what you do, in one line.
2. Expand with your philosophy or approach.
3. Name-drop a few recognizable brands.
4. End with what you're doing *now* and what you're looking for.

### Case Studies:
1. **Context:** What was the problem?
2. **Goal:** What were we trying to achieve?
3. **Process:** What did I do? (Be specific, admit limitations.)
4. **Outcome:** What happened? (Use numbers if possible.)
5. **Takeaway:** What did I learn? (Be reflective, not preachy.)

### CV Bullet Points:
1. Start with an action verb.
2. Include a metric or outcome.
3. Keep it to one line if possible.
4. Don't repeat the same verb twice in a row.

### LinkedIn Posts:
1. Hook in the first line.
2. Short paragraphs (1–2 sentences each).
3. End with a question or call to action.

## Voice Checklist (Before Publishing)

- [ ] Does this sound like something I'd say out loud?
- [ ] Are there any banned words or phrases?
- [ ] Is the sentence length varied?
- [ ] Are there contractions?
- [ ] Is there at least one specific detail or example?
- [ ] Is there any passive voice that could be active?
- [ ] Does it have a human edge (humor, opinion, honesty)?
- [ ] Would I cringe if I read this in a year?

## Examples

### ❌ Robotic:
> I am a seasoned professional with a passion for leveraging innovative
> solutions to deliver impactful results in the digital landscape.

### ✅ Human:
> I've been building things on the web for over 20 years. I care about
> clean design, code that works, and tools that don't get in your way.

---

### ❌ Robotic:
> Spearheaded cross-functional initiatives to optimize user engagement
> and facilitate seamless collaboration across departments.

### ✅ Human:
> I worked with developers, designers, and product managers to make the
> product easier to use — and actually shipped it.

---

### ❌ Robotic:
> The project was successfully delivered, resulting in a significant
> increase in user satisfaction metrics.

### ✅ Human:
> We shipped it. Users noticed. Support tickets dropped by 30%.

## Final Rule

If it sounds like it was written by a committee, a marketing department,
or an AI trying to impress a recruiter — rewrite it.

Write like a human. Write like Krisztián.
